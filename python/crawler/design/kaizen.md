## Skill friction
- 2026-11-10, update: the skill assumes one instruction file and one `design/` per repository; here kaizen is rolled out for one subproject (`python/crawler/`) while the top level is shared with colleagues, so every record's place had to be asked.
- 2026-11-10, sync: step 2 assumes `git fetch` from the tracker's remote; here `origin` is the legacy iffgit and GitHub is no remote yet, so it fetched the GitHub URL directly into `github/*`; `gh` is not installed, the public API stood in.
- 2026-11-11, requirements: the skill writes `design/requirements.md`, but the crawler keeps one requirements document per topic (`requirements.md`, `-pipeline.md`, `-benchmark.md`); and the hand-over's "quote every open item in full" does not fit the fifteen-line message limit once a document has twenty items.
- 2026-11-11, debrief (for upstream, @weber): the coaching judged choices that were deliberate as costs: a blanket yes to the leans (checked, and meant), a README approved on a skim (early stage, not yet for beta), exploring without a spec (a novel idea in a VM with git). What is better is debatable; the point is checking with the right level of care. Such points should be asked as questions ("was this deliberate, and at what level of care?"), not coloured good or bad.
- 2026-11-11, debrief: reader agents cite the file's line numbers instead of the `L<n>` markers in places (one reader gave L2326 for the moment marked L1111), so every citation had to be mapped back; the brief could ask readers to quote the marker line itself.
- 2026-11-16, walkthrough: the walks tested where material should *live* (kaizen, modama, separate repositories, personal), not a process of the project's product; the personas came from kaizen's own stakeholder record in another repository, and the acceptance examples had no fitting `design/examples.md` (the crawler's holds the search's), so they went into the routing file (`working-with-agents-routing.md`, RE1 to RE7). The version check exited 0 this time.
- 2026-11-12, hallway-test (run by an agent for an OpenSpec apply, no person in the loop): the settle-with-the-person steps (items 1 to 9, "Start?") had no one to ask, so the leans were taken from the task's brief; and `usage.py` found no transcript for a sub-agent of a worktree session, so the record has the notification's totals only.
