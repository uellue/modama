# Dataset recognition: prior art

Status: draft for review. Companion to `requirements.md`; references R*n* and Q*n* from there.

How this was made: three research agents read source code, documentation and issue trackers of the projects below on 2026-10-14 and marked every claim as verified (with URL) or recalled. I re-checked the seven claims marked ‡ myself. Nothing here is from memory alone; where a claim is only recalled, it says so. The full agent reports are longer and available on request.

## The projects, in one paragraph each

**shared-mime-info** (freedesktop.org): the MIME database we already use for single files. Declarative XML rules with glob weights and magic priorities, a checking order that goes name first and content only on conflict, a subclass hierarchy, and a monthly-ish release from one repository. See `../openspec/specs/mime-database/` for what we implemented.

**PRONOM, DROID, Siegfried** (digital preservation): a central registry of format signatures, maintained by The National Archives UK since 2002 with community contributions through [PRONOM_Research](https://github.com/digital-preservation/PRONOM_Research) (issue templates, CC0 sample files, weekly draft releases). Rules are pure XML byte signatures; priority is an explicit pairwise relation `HasPriorityOverFileFormatID` in the [signature file](https://cdn.nationalarchives.gov.uk/documents/DROID_SignatureFile_V120.xml). Siegfried, the fast matcher, makes the relation transitive and uses it to stop early. Every result carries a `basis` string such as `extension match; container name CompObj with byte match at 77, 20` ([wiki](https://github.com/richardlehane/siegfried/wiki/Identifying-file-formats) ‡) and warnings for extension mismatches and unknowns. Per-site rule sets are composed at build time with `roy build -limit/-exclude/-extend` ([wiki](https://github.com/richardlehane/siegfried/wiki/Building-a-signature-file-with-ROY)). A "skeleton test suite" generates a minimal file from every signature to find signatures that conflict ([generator](https://github.com/exponential-decay/skeleton-test-suite-generator)); its release repository was archived in 2023. Known pain: a rule language with no escape hatch, so [issue #292](https://github.com/richardlehane/siegfried/issues/292) (HTML matched as a Czech e-government format) can't be fixed in code; DROID and Siegfried apply priorities at different times and disagreed on polyglot files ([#52](https://github.com/richardlehane/siegfried/issues/52), [#146](https://github.com/richardlehane/siegfried/issues/146)).

**Apache Tika**: hybrid. A 1700-type XML file with magic priorities (integers, default 50, "negotiated" in comments like "should have a higher priority than rfc822", [tika-mimetypes.xml](https://raw.githubusercontent.com/apache/tika/main/tika-core/src/main/resources/org/apache/tika/mime/tika-mimetypes.xml)) plus a Java `Detector` service interface for anything the XML can't express. Every jar on the classpath may ship a `custom-mimetypes.xml`, which is merged additively; conflicting globs for unrelated types throw at load time. `CompositeDetector` runs all detectors and keeps a result only if it specialises the current one ([source](https://raw.githubusercontent.com/apache/tika/main/tika-core/src/main/java/org/apache/tika/detect/CompositeDetector.java) ‡), so order matters and unrelated answers are silently dropped. Deployment config excludes detectors and parsers by class name. No basis is reported; troubleshooting is `--list-detectors` and a hex editor. About 1200 test files, named after the ticket that introduced them, each detected twice: content only and content plus name. Pain: [TIKA-3554](https://www.mail-archive.com/dev@tika.apache.org/msg34822.html) (plain text named `.zip` reported as zip because the name hint wins when magic says octet-stream), [TIKA-4347](https://www.mail-archive.com/dev@tika.apache.org/msg46486.html) (same file detected differently from a stream and from a file, accepted as "a trade-off").

**file / libmagic**: 360 rule fragments, one per format family, compiled into one database. Priority is a computed "strength" from rule specificity (base plus 10 per matched byte, adjusted for operators), overridable per rule with `!:strength *3`, sorted descending with ties broken by a byte comparison of the rule struct ([apprentice.c](https://raw.githubusercontent.com/file/file/master/src/apprentice.c)). Tests are `X.testfile` and `X.result` pairs, one per bug and per new rule by convention ([tests/README](https://raw.githubusercontent.com/file/file/master/tests/README)). Single file only, no explanation of why a match won.

**Bio-Formats** (OME, ~160 microscopy readers in one Java codebase): each reader implements `isThisType(name, open)` with `suffixNecessary`/`suffixSufficient` flags, so a reader declares whether the name alone suffices and whether it may open the file. `ImageReader` walks a hand-ordered `readers.txt` and takes the first match; catch-all readers (any TIFF, any text) are forced last with comments. It is the only project with a real multi-file model: `getUsedFiles()`, `getAdvancedUsedFiles(noPixels)` for metadata-only companions, `getRequiredDirectories()`, `fileGroupOption()` returning MUST/CAN/CANNOT_GROUP, and a documented [dataset structure table](https://bio-formats.readthedocs.io/en/stable/formats/dataset-table.html) per format ("One .lei file with at least one .tif/.tiff file and an optional .txt file"). The test suite enforces "one reader, and only one reader, identifies the dataset as its own" for every used file, and that `isThisType` agrees with and without opening the file; the uniqueness test carries roughly 25 hard-coded exemptions for reader pairs that legitimately overlap ([FormatReaderTest.java](https://raw.githubusercontent.com/ome/bioformats/develop/components/test-suite/src/loci/tests/testng/FormatReaderTest.java) ‡). Expected results per dataset live in generated `.bioformats` INI files mirroring a private QA corpus. Pain: readers in other repositories still need a PR to the central list, called "does not scale" in [ome/design#42](https://github.com/ome/design/issues/42), open since 2016; a TIFF claimed by the DeltaVision reader on two magic bytes ([#2656](https://github.com/ome/bioformats/issues/2656)); the chosen reader depending on which member file was opened ([#2308](https://github.com/ome/bioformats/issues/2308)).

**RosettaSciIO and HyperSpy** (the EM community's IO plugins, split out of HyperSpy in 2022): one directory per plugin with a `specifications.yaml` (name, aliases, extensions, capabilities) and a `file_reader()`. Discovery walks the package, so there are no third-party plugins. HyperSpy picks by extension, raises if more than one plugin claims it, and falls back to the generic image reader if none does ([io.py](https://raw.githubusercontent.com/hyperspy/hyperspy/RELEASE_next_major/hyperspy/io.py) ‡); `hspy` and `usid` both declare `hdf5`, so the collision is built in, and NCEM EMD saved as `.hdf5` needed a manual override ([hyperspy#1478](https://github.com/hyperspy/hyperspy/issues/1478)). Test data: ~630 small files in the repository under `rsciio/tests/data`, excluded from wheels, fetched on demand with pooch from the tagged release with a sha256 `registry.txt` maintained by a pre-commit hook and an environment variable for mirrors ([registry.py](https://raw.githubusercontent.com/hyperspy/rosettasciio/main/rsciio/tests/registry.py)). Policy: smallest possible files, non-square grids, zeros compress well; no licence per file.

**LiberTEM**: 16 dataset types; `DataSet.detect_params(path)` returns parameters or `False`. `detect()` tries types claiming the extension first, then the rest in registration order, first non-empty wins ([`__init__.py`](https://raw.githubusercontent.com/LiberTEM/LiberTEM/master/src/libertem/io/dataset/__init__.py)). Raw files are never auto-detected. EMPAD detection runs full initialisation and returns `False` on any exception, losing the reason. HDF5 detection walks the file for 3-D datasets under a 3 s timeout, added after a Matlab 7.3 `.mat` file whose `h5dump --header` was 100 MB locked a worker for minutes ([#440](https://github.com/LiberTEM/LiberTEM/issues/440) ‡, fixed in PR #449). Companions: EMPAD XML to raw via the basename in the XML, K2IS `.gtg` plus eight `.bin`, FRMS6 `.hdr` plus `*_NNN.frms6`, MIB `.hdr` plus `.mib`, with a `disable_glob` escape hatch. Test data mostly synthetic; the real corpus is unpublished.

**Galaxy datatypes** (negative example): about 309 sniffers in one hand-ordered XML list, "most rigidly defined first", first match wins; datatypes not listed are appended after the generic types and never match. One good idea: a shared `FilePrefix` of 1 MiB read once for all sniffers. Pain, all recent: [PR #23273](https://github.com/galaxyproject/galaxy/pull/23273) ‡ (Sep 2026: new sniffers "get appended to the end of `sniff_order` and sit behind the generic types"; "The doctests miss this because they call `sniff()` directly rather than going through `sniff_order`"; a suffix rule "claims all NeXus files"); [PR #23916](https://github.com/galaxyproject/galaxy/pull/23916) (a reviewer re-sniffed all 336 fixtures by hand because no test covers the global order); [#9176](https://github.com/galaxyproject/galaxy/issues/9176) (a third-party datatype package overrode a built-in; maintainer: "Issues like this is why I discourage tool shed based datatypes"); every sniffer call wrapped in `except Exception: pass`.

**Plugin mechanics in Python**: `importlib.metadata` entry points discover plugins without importing them, in `sys.path` order, with duplicates undetected and `load()` unguarded ([CPython](https://raw.githubusercontent.com/python/cpython/main/Lib/importlib/metadata/__init__.py)). pytest loads the `pytest11` group, blocks plugins with `-p no:name`, and aborts the whole run on an import error. stevedore adds what entry points lack: `NamedExtensionManager(names, name_order=True)` for an explicit ordered list, `on_load_failure_callback` to continue past a broken plugin, and `conflict_resolver=error_on_conflict` to raise on duplicate names ([docs](https://docs.openstack.org/stevedore/latest/reference/index.html) ‡). datalad-metalad extractors are entry points with a fixed UUID and version per extractor and an `is_content_required()` split between metadata-only and content stages ([docs](https://docs.datalad.org/projects/metalad/en/latest/user_guide/writing-extractors.html)).

**Test-data hosting**: pooch (registry of hashes, cache directory, per-file URLs, environment overrides) as used by scikit-image and RosettaSciIO; git LFS counts against repository quota and is re-downloaded by every CI clone; Zenodo records are immutable, 50 GB each, with a concept DOI across versions ([policies](https://about.zenodo.org/policies/)); GitHub release assets must be under 2 GiB per file. pyvista's hash-less registry is the anti-pattern.

**Earlier evaluation on MR !106** (@weber, @clausen, June 2026): PRONOM PUIDs were judged inaccessible from Python (Java tooling, opaque identifiers like `fmt/40` where `application/msword` says more); MIME types were found to be the only cross-discipline standard, with gaps for NPY and IPYNB that unofficial types in the wild fill; magika (Google's content classifier, suggested by @shanker) recognises those but still reports the generic MIME type; pyxdg was chosen as the most extensible MIME infrastructure. Caveats found then: host-installed packages add definitions and cross-talk with ours, DM3/DM4 come from gwyddion by extension only, and `*.raw` is claimed by Panasonic raw images, which a custom `application/octet-stream` glob entry overrides to force content matching. `XDG_DATA_HOME` redirects the user database; `XDG_DATA_DIRS` would be needed to drop the system one.

## Lessons, by question

### Q6: declarative rules or code?

Every mature system ended up hybrid. PRONOM is pure data and can't fix #292 in code; Tika's XML header says "For logic too complex to be expressed in a magic match, provide a Custom Detector"; libmagic's DSL grew subroutines (`name`/`use`) and `indirect`; Bio-Formats and LiberTEM are pure code and pay for it with hand-ordered lists and detection that initialises the whole reader. The declarative part is what makes conflict analysis and skeleton tests possible without running anything; the code part is what keeps rare cases fixable.

For us: declare the cheap part (names, globs, magic, sibling patterns, directory markers) as data that the core can analyse, and keep content probes as code with a declared budget. Nobody has a declarative language for multi-file datasets, so that part will be ours either way.

### Q5: priority and ambiguity

Four mechanisms exist, and all four have evidence against them when used alone:

| Mechanism | Used by | What went wrong |
|---|---|---|
| One hand-ordered global list | Bio-Formats, Galaxy | Unlisted sniffers never run (Galaxy #23273); catch-alls need comments like "must go last"; no test of the order itself (Galaxy #23916) |
| Global integer priority | Tika, shared-mime-info | Values negotiated by hand in one file ("higher priority than matlab's priority=20"); needs a central editor for every pair of contributors |
| Pairwise "wins over" relations | PRONOM | Needs the registry to know both formats; two tools applied it differently and disagreed (#52, #146) |
| Computed specificity with override | libmagic | Length heuristic, short-but-unique magic loses to long generic patterns; undocumented tie-breaking |

Two things did work across projects: a **type hierarchy** so that a specific result refines a generic one (Tika `sub-class-of`, shared-mime-info `sub-class-of`, Bio-Formats' delegate readers), and an **explicit "ambiguous" outcome** instead of a forced winner (Siegfried's `single` mode returns UNKNOWN with a "multiple matches" warning; HyperSpy raises; Siegfried's default mode funnels to the most specific match and was criticised for it in #146).

For us, as recommended on 2026-10-14: computed specificity as the default order, a hierarchy for refinement, explicit ambiguity as a first-class result. Decided otherwise the same day (`architecture.md` C): the XDG 0..100 model, because it is proven and understandable; the hierarchy and explicit ambiguity were kept, and after the critique ties resolve to the common ancestor in the `sub-class-of` hierarchy rather than to `application/octet-stream`.

### Q1–Q4, Q11: multi-file datasets

Only Bio-Formats has a model, and it is worth copying in spirit: an entry file, the list of used files, metadata-only companions, how many parent directories matter, and whether the files must, can or can't be grouped. Its tests show what to check: every used file claimed by exactly one reader, re-detection from any member reproducing the same used-file list, and the same answer with and without opening the file. Its bugs show what goes wrong: the chosen reader depending on which member you start from (#2308), and renaming any companion breaking the dataset.

None of PRONOM, Tika, libmagic, Galaxy or RosettaSciIO looks at sibling files at all. LiberTEM finds companions by naming convention next to the entry file, and HDF5 external links, the family driver and virtual datasets mean an `.h5` file can reference siblings invisibly, with missing sources silently replaced by fill values ([VDS docs](https://support.hdfgroup.org/documentation/hdf5/latest/_v_d_s_t_n.html)). Zarr v2 and v3 mark the dataset directory with `.zarray`/`.zgroup` or `zarr.json`, and OME-Zarr adds `attributes.ome`; the marked directory is the dataset and nothing below it should be visited ([Zarr v3](https://zarr-specs.readthedocs.io/en/latest/v3/core/index.html)).

For us: recognition needs the directory listing as input, not just one file (Q11). The anchor should be the file a handler can recognise on its own, which for header+data pairs is the header and for directories is the directory (Q4). Membership exclusivity (Q1) is what Bio-Formats enforces and what made its exemption list grow; the alternative, letting metadata-only files such as a README belong to several datasets, has no precedent in these projects.

### R7, R12: cost and robustness of probes

Galaxy reads one 1 MiB prefix shared by all sniffers, and forbids whole-file reads for production datatypes, but legacy sniffers still spawn `pysam.index` on BAM files. LiberTEM needed a timeout after the 100 MB-header Matlab file (#440); this is your earmarked test case, and it shows that a byte budget alone isn't enough, a time budget is needed too. Tika's results differ between streaming and file-backed input (TIKA-4347). Bio-Formats' `isThisType` must give the same answer with and without opening the file.

For us: a bounded shared prefix per file, a time budget per probe, and the rule that a probe returns a reason, never a bare `False` (LiberTEM's EMPAD detection and Galaxy's `except: pass` both lose the reason).

### R1, R2: registration and per-deployment composition

Projects that keep one central list (Bio-Formats `readers.txt`, Galaxy's XML, PRONOM) all hit the "external contributors need a PR to the core" problem (ome/design#42, Galaxy #9176). Tika and metalad use a service-loader pattern where any installed package can contribute, and Tika merges per-package override files additively. Deployment composition exists as exclude lists (Tika `detector-exclude`), explicit ordered include lists (stevedore `NamedExtensionManager`), and build-time rule-set composition (`roy build -limit/-exclude/-extend`).

For us: entry points for discovery, an explicit per-deployment list of enabled handlers (R1) rather than "everything installed", load failures collected into a report instead of aborting (stevedore) or silently dropping (Galaxy), and duplicate names rejected at load time.

### R4, R5: detecting cross-talk

What exists: Bio-Formats' exactly-one-reader test over a corpus; Tika's load-time check that unrelated types don't share a glob and its detection tests run with and without the file name; PRONOM's skeleton files generated from every signature to make conflicts visible without real samples; Siegfried's test that every skeleton file yields exactly one match; libmagic's duplicate warning at compile time. What is missing everywhere: a test of the *order* itself, which is why Galaxy reviewers re-sniff all fixtures by hand.

For us: conflict analysis on the declared rules at load time (globs, magic, sibling patterns), skeleton files generated from the declarations, and a corpus test that reports every file with zero or more than one claimant, with an exemption list that is data in the deployment, not code in the test.

### R13, Q8: test data

The RosettaSciIO pattern fits an EM project with many small formats: tiny real files next to the handler, a hash registry kept by pre-commit, fetched from the tagged release through pooch, with an environment variable pointing at a local mirror for offline runs. For files beyond a few MB, Zenodo gives immutable, citable storage with versioning; git LFS costs quota and CI bandwidth on every clone. Bio-Formats and LiberTEM both keep their real corpora private, which blocks outside contributors from reproducing failures. None of the projects records a licence per test file.

For us: each handler package ships its small fixtures and a registry; large files go to Zenodo or an institute store with hashes and a licence note per file; synthetic files where a format can be generated (PRONOM's skeleton idea, LiberTEM's `_mk_random`); and a deployment runs the tests of all installed handler packages against one shared cache.

### R8, R9: explainability and provenance

Siegfried is the model: every match has a basis string and structured warnings, and unknowns list the candidates that were excluded by content. Tika and libmagic have nothing comparable, and their bug reports show it. metalad gives every extractor a fixed UUID and version, so a stored result says which extractor produced it.

For us: store handler name and version plus a basis with every dataset and every unclaimed file, so a failure report from production is already a test case.

## What the survey did not settle

- How to express **sibling and directory rules** declaratively. No precedent; Bio-Formats' dataset table is prose.
- Whether **membership is exclusive** (Q1). Bio-Formats says yes and lives with exemptions.
- How to handle **incomplete datasets** during copying (Q3). No project crawls a live file system; all of them open finished files.
- **Collapsing large trees** (R11, Q9). Only Zarr's "don't descend below the marker" is documented; nothing for `node_modules` or environments.
- Whether a **computed specificity** can be defined for our mixed rules (names, magic, siblings, markers) in a way contributors find predictable. libmagic's experience says the heuristic will need overrides.

## Rule selection and rule-package distribution (added 2026-10-16)

For Q17: how a deployment selects handlers from many collections, and how such packages are found. Verified against the projects' documentation on 2026-10-16; I re-checked the ruff quotes.

| Project | Selection syntax | Precedence | Per-path | Distribution and discovery |
|---|---|---|---|---|
| [ruff](https://docs.astral.sh/ruff/settings/) ‡ | `select`, `ignore`, `extend-select`, prefixes (`F`, `F4`, `F401`, `ALL`) | "more specific prefixes override less specific prefixes"; "`ignore` takes precedence over `select` if the same prefix appears in both" | `per-file-ignores` with globset patterns, `!` negates; additive only: letting negated patterns re-enable rules was tried and reverted as "too confusing" ([#10863](https://github.com/astral-sh/ruff/pull/10863)) | built in |
| [flake8](https://flake8.pycqa.org/en/latest/user/options.html) | same model, which ruff copied | "the most specific user-specified rule will win" | `per-file-ignores` | plugins via entry points `flake8.extension`, whose name is a unique code prefix; `Framework :: Flake8` classifier; an awesome list |
| [clang-tidy](https://clang.llvm.org/extra/clang-tidy/) | ordered glob list `-*,clang-analyzer-*,-clang-analyzer-cplusplus*` | "Globs are processed in order of appearance"; CLI appended to the config file | none | compiled in |
| [ESLint](https://eslint.org/docs/latest/use/configure/configuration-files) | ordered list of `{files, ignores, plugins, rules}` objects, severities off/warn/error | "later objects overriding previous objects" | `files`/`ignores` per object, minimatch | `eslint-plugin-*` on npm, rules namespaced `plugin/rule`, awesome list (~250) |
| pylint | symbolic names, ids, categories, `all` | positional: `--disable=all --enable=classes --disable=W` | inline comments | `load-plugins` |
| [RuboCop](https://docs.rubocop.org/rubocop/latest/configuration.html) | `Department/Cop`, department toggle, per-cop `Enabled`, `DisabledByDefault` | cop overrides department; file over inherited; `Exclude` beats `Include`; arrays replace on inheritance | `Include`/`Exclude` per cop | `rubocop-*` gems via `plugins:`; new cops are "pending" and warn until enabled or disabled |
| [Semgrep](https://docs.semgrep.dev/running-rules) | `--config p/python`, `--exclude-rule id` | "exclusion filters take precedence" | rule-level `paths: include/exclude` | central registry, rules by pull request with mandatory tests and metadata; registry pulls send metrics by default |
| [pre-commit](https://pre-commit.com/) | `repos:` with git URL, pinned `rev`, hook ids | n/a | `files`/`exclude` as Python regexes | hooks from git repos, `autoupdate` for versions; curated page by pull request, with criteria (over 500 stars) |
| [pytest](https://docs.pytest.org/en/stable/how-to/writing_plugins.html) | `-p no:name` | n/a | n/a | entry point `pytest11`, `pytest-*` names, `Framework :: Pytest`, an auto-generated list of 2,016 plugins |
| [gitignore](https://git-scm.com/docs/gitignore) | patterns with `!`, `**` | last match wins; no re-include under an excluded directory | the standard everyone reuses (ESLint, ruff, Semgrep) | n/a |

Lessons: the ruff/flake8 model is the one Python developers know and its precedence fits in one sentence, while positional models (clang-tidy, pylint) are compact but easy to get wrong when sources are concatenated. Namespaced ids (`plugin/rule`, `Department/Cop`) read better than codes. Per-path overrides should be gitignore globs and additive only. New rules after an upgrade are handled either by implicit enabling (ruff `ALL`) or by a pending-state warning (RuboCop). Distribution is entry points plus a name prefix plus a curated page everywhere; Semgrep's central registry is the outlier and brings a network dependency.
