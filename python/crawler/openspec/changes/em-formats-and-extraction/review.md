# Review of the implementation, 2026-11-11

By an agent that did not write the code (commit eb425ae), given the code, this change's specs and `design/requirements.md`. Findings verified before acting: the orchestrator re-ran the reviewer's scratch tests, which reproduced; each fix comes with a test in the repository that fails before it and passes after (the tests of finding 7 cover behaviour that was already right). The full report is in the session transcript.

| # | Finding | Outcome |
|---|---|---|
| 1 | Extracted values that JSONB rejects (NaN, infinities, `\x00`, lone surrogates) made `store()` raise: the whole crawl failed, every night | Fixed: the worker replaces NUL and lone surrogates by U+FFFD, cuts strings to 4096 characters and lists and mappings to 1000 entries, and checks with `json.dumps(allow_nan=False)`; what still cannot be stored is the dataset's extraction error. Spec: requirement "Formats may extract metadata". Test: `test_values_the_database_rejects` |
| 2 | Failures of the environment (timeout, dead worker, OSError such as ESTALE, ImportError) were reused as if they were the file's; so were directories whose recognition met a read error or the time limit | Fixed: `Extraction.retry` (column `extract_retry`) marks them, and they are not reused; a deterministic failure (the reader raising on the content, MemoryError under the budget, an unstorable result) still is. A directory listing carries `retry` (column `directories.retry`) when MIME detection could not read a file, a format raised OSError or ran over its time limit; it is not taken over. Spec: scenario renamed "A file whose reading failed stays failed until something changes", new "A timeout is retried on the next crawl". Tests: `test_a_timeout_is_retried_on_the_next_crawl`, `test_other_failures_of_the_environment_are_retried`, `test_a_directory_whose_recognition_met_the_environment_is_recognised_again` |
| 3 | A directory the crawler cannot list made all its ancestors "changed" on every crawl | Fixed: it is stored with the digest `cannot list` and counts as unchanged when it was unlistable last time too; its entry in the parent is compared by the parent's listing. Test: `test_an_unlistable_directory_leaves_its_ancestors_unchanged` |
| 4 | Collapsed datasets shared one constant stamp (of no members) | Fixed: stamped with their directory's listing digest. Test: `test_a_collapsed_dataset_is_stamped_with_its_listing` |
| 5 | No memory budget for extraction | Fixed: `RLIMIT_AS` in the worker initializer, 4 GiB by default (a worker with RosettaSciIO and numpy maps about 0.4 GiB on 8 CPUs), `MODAMA_CRAWLER_EXTRACT_MEMORY` in MiB; `max_tasks_per_child=100`; a Merlin `.hdr` over 64 KiB is not parsed. The private `rsciio.quantumdetector._api` use is noted next to the exact pin in `pyproject.toml`. Tests: `test_an_extractor_runs_out_of_memory`, `test_an_oversized_header_is_not_parsed` |
| 6 | The rule-set fingerprint did not cover the crawler's version nor the collections' distribution versions | Fixed: the versions of `modama-crawler` and of the distributions that provide the enabled formats' modules are in it. Test: `test_the_fingerprint_covers_the_distribution_versions` |
| 7 | Tests missing: "datasets of that extractor only", "only records whose content changed get a new datestamp" from both sides, a rewrite with the same size and restored mtime | Fixed: a second stand-in format (`Other`) and a stand-in output that depends on the extractor version, in `test_a_new_extractor_version`; `test_a_rewrite_with_the_same_size_and_mtime` (seen through the ctime) |
| 8 | The main connection sat idle in a transaction for hours during walk and extraction | Fixed: `crawl_tree` commits and runs walk and extraction in autocommit, then stores in one transaction as before. Test: `test_walk_and_extraction_leave_no_transaction_open` |
| 9 | `test_an_extractor_hangs` with a 3 s limit could time out the quick task on a loaded runner (the time includes starting the process) | Fixed: 10 s limit in the test |
