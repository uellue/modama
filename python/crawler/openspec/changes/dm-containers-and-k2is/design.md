# Design

## Context

See proposal.md, Why. The DM types in `dm/dm.xml` have magic and no globs, on purpose (a misnamed `.dm4` is typed by content). The crawler's MIME detection follows the shared-mime-info order (spec `mime-database`, "Names decide, content resolves"): a name rule decides, and a name match that is a subclass of the sniffed type wins. No core type has a `*.dmw`, `*.gtg` or `*.bin` glob (checked in `formats/core/freedesktop.org.xml` and `er-c.xml`). The Merlin part (`merlin/`) is the pattern for an acquisition of a header and frame files: types for both, a recognizer that groups by stem, a warning for frames without a header.

## Goals / Non-Goals

**Goals:** honest types for `.dmw` and `.gtg`; one dataset per K2IS capture; the tags of a K2IS `.gtg` in its description.
**Non-Goals:** K2IS frame counts or data; `.dmw` metadata; LiberTEM as a dependency.

## Decisions

**D1. Types by name, as subclasses of DM4.** `application/x.dm-dmw` (glob `*.dmw`, in `dm/dm.xml`) and `application/x.dm-gtg` (glob `*.gtg`, in `k2is/k2is.xml`, since the K2IS part reacts to it and each part is tested with its own definitions plus the core's), each `sub-class-of application/x.dm4`. The name decides; content would say DM4, and the name match, being its subclass, wins. The DM4 format reacts to `application/x.dm4` only, so neither type is extracted as an image. Comments say what is verified: "Gatan Digital Micrograph .dmw file" and "Gatan Digital Micrograph .gtg tag file" (LiberTEM calls it "the .gtg file"; Gatan's own names to be confirmed, open question).
*Alternative:* a content rule (no `ImageList` tag): the tag tree is not at a fixed offset, so magic cannot see it; the extractor would have to type files, which is recognition's job.

**D2. K2IS sector files by content.** `application/x.k2is-sector` with magic (priority 60): `big32` `0xFFFF0055` at 0, `big16` 256 at 20, `big16` 1860 at 22, LiberTEM's `DataBlock.is_valid` (the block header layout `header_dtype`: sync, 4 bytes padding, version, flags, 6 bytes padding, block count, then width and height). No glob: `*.bin` is everybody's.

**D3. Grouping as LiberTEM does, with two steps away from it.** In a new part `k2is/`: for each `.gtg` (longest stem first, as Merlin), the sector files whose names start with the `.gtg` file's stem (`X_.gtg` takes `X_*.bin`); exactly 8 make a dataset anchored at the `.gtg` (`NUM_SECTORS`); otherwise nothing is claimed, and a `.gtg` with some sector files gets a warning that names it and their number ("X_.gtg: 7 sector files X_*.bin, a K2IS acquisition has 8"). Sector files of no `.gtg`: one warning per directory, as Merlin's orphans. A `.gtg` without sectors stays a single file, no warning (configuration files like `IDES_DMS_Config.gtg` exist). Away from LiberTEM (review finding 3, decision 130): (a) a sector file belongs to the longest stem it starts with, whether that stem has 8 sector files or not, so that an incomplete `scan_2_.gtg` does not break a complete `scan_.gtg` next to it (LiberTEM would glob `scan_*.bin`, find 15 and refuse `scan_.gtg`). The price: a `.gtg` whose stem starts a sector name of another (`X_1.gtg` next to `X_.gtg` with `X_1.bin` to `X_8.bin`) takes that sector, and neither forms a capture, with a warning for each; not seen. (b) `.bin`, like `.gtg` (shared-mime-info globs ignore case), in any case: LiberTEM lower-cases the extension of the path it is given, and globs `*.bin` case-sensitively on Linux but not on Windows, where Gatan Microscopy Suite writes the files; whether it writes `.BIN` is not known.

**D4. Extraction from the `.gtg` tags only.** RosettaSciIO's `DigitalMicrographReader` on our own handle (64 KiB buffer, readahead off, as `dm.first_image` on branch `dm-handle`), `parse_file`, then the tag tree, without image dictionaries (a `.gtg` may have none). The description gives every tag of the `.gtg` but GMS's user-interface settings (decision 129: "everything except things like GMS GUI settings (e.g. window size and position)"), each under its path of tag names and with its value as the reader gives it, not rounded and with no unit joined (README, "Values and units"), for example `SI Dimensions.Size X 35`, `DataBar.Device Name K2-IS-0001`, `Acquisition.Frame.CCD.Pixel Size (um) (10.0, 10.0)`. First the groups LiberTEM reads for the scan shape (`SI Dimensions`, `Size X`, `Size Y`, at the root as `_get_nav_shape` reads `.SI Dimensions.Size X`) and `Microscope Info` at the root, then the other tags in the reader's order. Tags without a value stay, as the reader gives them (`[]` for an empty string, e.g. `Session Info.Operator []`): decision 161, @weber 2026-11-12, "keep the empty tags, we can eliminate them if needed later". The number of files and their size are in the basic description already. Subjects: the display name "Gatan K2 IS" and the microscope name if present (the string tag `Name` of the root's `Microscope Info`; `FEI Tecnai Remote` in Capture52).

The user-interface settings, an explicit list (since 2026-11-12 the one skip list in `dm/__init__.py`, `dm.skipped`), identified in Capture52's `.gtg` (359 tags; 52 left out, 307 shown, 11 of them without a value):
- a tag group whose `Class Name` is `cm_stdviewerimagedisplayer`, the image viewer: `Window Relative Position`, `Screen Relative Position`, `Zoom`, `Do Auto Zoom`, `View Name`, `Viewer Class`, `Version` and the `Class Name` itself (in Capture52 `Acquisition.Parameters.Objects.TagGroup1` and the same under `SI Image Tags`, 16 tags);
- the group `Items` in `Session Info`: the definition of GMS's Session Info form, per field `Label`, `Tag path`, `Data Type`, `Precision`, `Units` and `Value` (36 tags); the fields' own values (`Session Info.Specimen`, `Operator`, `Microscope`) stay, empty in Capture52.

Kept, though near them: the other processing objects of the acquisition (`cm_imgproc_finalcombine`, `cm_imgproc_histogram`, `cm_softwarebinning`), the camera's parameter set (`Parameter Set Name Search`, `Parameter Set Tag Path Imaging:View:Search`), DigiScan's `Zoom factor` (the scan's field of view) and the survey image's `Spectrum Image Rect`. The description is long (307 phrases, about 19,000 characters for Capture52, `SI Image Tags` repeating much of `Acquisition`); trimming it on human feedback from real files is a backlog item ("DM and K2IS tags", formerly "K2IS description", `BACKLOG.md`, "K2IS description").
*Alternative:* a short list of exact tag paths (review finding 2); not chosen (decision 129). The 4D-STEM subject as EMPAD has it when a scan exists: not added.

*Changed 2026-11-12* (@weber, item 228 and "for all dm derived formats we better use original_metadata"): the tags, filtered as above, go into the extraction's values (`original_metadata`, path to value, decision 230), not into the description, which began with `SI Dimensions.Size X 35, SI Dimensions.Size Y 34, Microscope Info.Cs(mm) 0.0, …` and was cut off before the useful part in Matchmaker. The description starts with a short summary line built by the rule DM images use (`dm.headline`, the tags in `dm.HEADLINE`, their values as the file holds them; spec `formats/dm`, "The summary line of a DM file's tags"); subjects add the imaging mode and the camera model. Open (decision 231): the summary line or the tags as `name: value`. After the review of 2026-11-12 (decision 235: "everything that is not obviously uninteresting"; @weber: "a negative 'skip these' list"): one skip list in `dm/` (`dm.skipped`: the user-interface settings above, the document's, page's and window's settings at the root, the older Session Info form under `Microscope Info.Items`, a workspace's `Window N`, and values not suitable for text, `values.textual`) serves DM images, K2IS and `.dmw`/`.dmwx`; `.dmw` and `.dmwx` keep their tags in their description, a workspace holds no image tags (decision 173).

## Risks / Trade-offs

- [The tag names are LiberTEM's, checked on one real `.gtg` only] → Capture52 (task 3.1) has `SI Dimensions` and `Microscope Info` at the root, where LiberTEM reads them; other GMS versions may name or nest tags differently: missing tags are left out, not guessed.
- [A `.dmw` that does hold an image is no longer extracted] → none seen: all 2,036 on staging failed for lack of an `ImageList`.
- [Fixtures] → a real K2IS capture since task 3.1 (Capture52, metadata only: the `.gtg` whole, the sectors cut to their first block's header); its `.gtg` also stands for the lone `.gtg`. No real `.dmw` yet (task 3.3): its fixture is a DM4 image of RosettaSciIO's test data, renamed, which holds an image where staging's `.dmw` files hold none. Representative files from staging need @weber's agreement per file.
