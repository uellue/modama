# modama-formats-em

Electron microscopy formats for the modama crawler (`python/crawler/`), as the format collection `em`. Install it next to the crawler and the crawler finds it through the entry point group `modama.formats`; its format ids start with `em/`.

| Format | Recognised as | Extracted |
|---|---|---|
| EMPAD | the XML header with the raw file it names, one dataset (`em/empad`) | a summary line: series count or scan size, exposure, time, as the header writes them after their names, for example `scan_resolution_x 32, scan_resolution_y 64, exposure_time 1 (unit unknown), 2026-03-25T16:47:52.586728`. Values: every element and attribute of the header as text under its dotted path (`timestamp.@isoformat`, `scan_parameters[2].scan_size`) but values not suitable for text, as `original_metadata`; scan size or frame count, frame size, exposure and time as computed (`mapped_metadata`); stored with the dataset, not in the record |
| Gatan Digital Micrograph | DM3 and DM4 files by their header, whatever their name (`em/dm3`, `em/dm4`), except `.dmw` and `.gtg` files: types of their own by name, not images | a summary line: the values of chosen tags of the data image (not the thumbnail), as the file holds them (`dm.HEADLINE`: imaging and operation mode, illumination mode, voltage, magnification, STEM camera length, camera model, detector, exposure, parameter set, the size as the reader gives it, date and time, specimen and operator), a number after its tag's name, not when it is 0; for example `Lorentz, TEM NANOPROBE, 300kV, 11.5kx, K2 summit, K2-0001, Exposure Time (s) 2.0, Search, y 3838, x 3710, scale 0.45048588514328003 nm, 7/17/2018, 3:29:20 PM`. Values: every tag of RosettaSciIO's `original_metadata` but one skip list (`dm.skipped`: Gatan Microscopy Suite's user-interface settings, the document's, page's and window's settings, values not suitable for text), flat under its dotted path, then RosettaSciIO's mapping as `mapped_metadata` and `axes`; stored with the dataset, not in the record |
| Gatan Digital Micrograph workspace | a `.dmw` file with the DM3 or DM4 header, one dataset (`em/dmw`); a DM3 one is marked as a file of interest in its basis; a `.dmw` without the header gets the type it has without the name (a text file: `text/plain`). As GMS writes it, a workspace holds root tags only: the file count, each image's name (a Windows path relative to it), frame and window, and the workspace's name; the images it names are separate datasets | every tag under its path, in the reader's order, but the skip list of DM files (its windows `Window 0 (…)` among them), for example `File name 0 .\exemplary_workspace\h1.dm4`; stored as every extraction, each phrase cut to 4,096 characters, at most 1,000 |
| Gatan Digital Micrograph workspace (compressed) | a `.dmwx` file, a ZIP whose first member is the workspace `<name>/<name>.dmw`, followed by `<name>/files/` with its images, one dataset (`em/dmwx`); one that is not a ZIP, or has no `.dmw` first, gets the type it has without the name | the inner workspace's tags, then each member's name and size; only the central directory and the workspace are read, no image |
| K2IS | a `.gtg` tag file with its 8 sector files `<stem>*.bin`, one dataset (`em/k2is`), whatever the `.gtg` holds (a broken one fails at extraction); sector files by their block header, whatever their name; sector files without their `.gtg`, or a `.gtg` with 1 to 7 or more than 8, stay single files with a warning; a `.gtg` without sector files stays a single file without a warning if it has the DM4 header, or the DM3 header (then marked as a file of interest in its basis), and otherwise gets the type it has without the name | the summary line of DM images from the `.gtg` tags, with the scan (`SI Dimensions`), for example `IMAGING, SCANNING, STEM NANOPROBE, 300kV, 320kx, STEM Camera Length 275.0, K2-IS, K2-IS-0001, Exposure Time (s) 0.0025, Search, Size X 35, Size Y 34, 3/29/2018, 1:28:03 PM`; every tag of the `.gtg` but the skip list of DM files kept as values (`original_metadata`), as for DM images |
| Merlin | the `.hdr` text header by its content with its `.mib` frame files, one dataset (`em/merlin`); `.mib` files without a header stay single files with a warning | a summary line: frame count, frame size, counter depth, readout system and time, as the header writes them (a number after its key), the frame size from the first frame's header (X, Y), for example `Frames in Acquisition (Number) 1, frame 256, 256, Counter Depth (number) 6, Merlin Quad, 15/04/2021 14:43:23`. Values: every `key<TAB>value` line of the header as text but values not suitable for text (`original_metadata`); frame count, frame size, counter depth, readout system and time as computed (`mapped_metadata`; no time, with a warning, for a date not in the form dd/mm/yyyy hh:mm:ss); stored with the dataset, not in the record |

Metadata extraction uses [RosettaSciIO](https://github.com/hyperspy/rosettasciio) (GPL-3.0-or-later), a dependency of this package only, for DM, `.dmw` and `.gtg` (its reader classes on a file we open with a 64 KiB buffer and readahead off: the tags are parsed, the image data skipped; Python's default buffer on NFS is 1 MiB, refilled at every seek) and Merlin (its parser of the first frame's header; the `.hdr` header we read ourselves in Latin-1, as the Merlin software writes "µ" as the byte 0xB5). Merlin frames belong to the header whose name they start with, as LiberTEM groups them (`acq.hdr`: `acq*.mib`). The extraction tests print each fixture's description, subjects and the bytes read (`pytest -s src`).

## Values and units: what the driver says

An extractor shows what the file or its reader (the format driver, for example RosettaSciIO) says, without editorializing: no number rounded (the DM reader's `18.325349807739258`, not `18.3`), no unit guessed from a value's size, no unit converted, no number from one tag joined with a unit from another. Where the driver gives no unit, the description says so ("unit unknown"). Consistent units and metadata blocks (with pint or similar) come later, in the drivers upstream where possible (@weber, 2026-11-11).

**What the file says comes first** (@weber, 2026-11-12, decision 230). For every format read through RosettaSciIO, the values are its `original_metadata` first: complete, as the instrument wrote it, minus GUI settings (window, page and display settings) and large arrays. The mapped metadata (HyperSpy's standard names) is kept as a second, labelled section, for comparing across formats; its conversions are RosettaSciIO's, shown as such, and where it disagrees with the original, the original wins and the difference goes to the RosettaSciIO list in `python/crawler/BACKLOG.md`. Getting the meaning of metadata right across vendors, reliably, is a big project of its own and out of scope here: the record represents to the user what is in the file, without editorializing, and the user makes their own sense of it. Open (decision 231): whether the summary line, today a few chosen tags, stays, or the record shows the tags as `name: value` just as they are found in the file. Files bring tags nobody has seen before, so what is kept is every tag minus a skip list, never a list of wanted tags (@weber, 2026-11-12: "we don't keep a positive list, but a negative 'skip these' list"); the summary line's few chosen tags are the only positive list.

**Not suitable for text** (@weber, 2026-11-12): a value too large or binary is left out, by one check for every format, `modama_formats_em.values.textual(value) -> bool`: lists and arrays of more than 16 items (`MAX_ITEMS`; the longest list of values about the data in RosettaSciIO's DM test files has 4, the shortest blob or array 60), strings of more than 1,000 characters (`MAX_CHARS`; the longest seen has 115) or with control characters other than tab and line ends, bytes, NumPy arrays that are not numbers, and RosettaSciIO's marker of an array it did not read. The DM part's skip list (`dm.skipped`) uses it, for DM images, K2IS and workspaces alike, and so do Merlin and EMPAD; everything it does not name is kept, a tag never seen before too.

## Setup and tests

```bash
uv pip install --python ~/.venv/bin/python -e python/crawler[test] -e python/modama-formats-em
cd python/modama-formats-em && pytest src
```

Each format is a subpackage of `src/modama_formats_em/` with its MIME rules, fixtures and tests, written as `python/crawler/src/modama_crawler/formats/TEMPLATE.md` describes; the crawler's pytest plugin runs them. Real files as fixtures are added only with agreement on each file.
